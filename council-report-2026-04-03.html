LLM Council Verdict

April 3, 2026 — Next step for March Madness pool optimizer

Question: The noseed model significantly beats seed on Brier accuracy (p=0.0006, 1071 games) but no mode shows significant pool EV advantage across 17 tournament years. Seed mode produces zero leverage picks. What should be the next step — Monte Carlo simulation, ship as-is, improve the model, fix the optimizer, or something else?

Council Verdict

Do Option D (audit the optimizer) before Option A (Monte Carlo), in that order.

Zero leverage picks from seed mode is the most important diagnostic signal. Before simulating anything, verify the optimizer produces correct leverage picks on a known non-chalk probability distribution. This is a synthetic test that takes hours, not days. Only after passing that gate: run Monte Carlo.

Where the Council Agrees

  • Audit before simulate. Every peer review ranked the Contrarian's sequencing as the strongest position. Zero leverage from seed mode is a failure signal that must be diagnosed.
  • Don't ship as-is (Option B). No one defended it. Shipping an unvalidated pool optimizer is intellectually dishonest.
  • Don't improve the model (Option C). Brier is already significant at p=0.0006. The problem isn't model accuracy — it's the unvalidated link between accuracy and pool EV.

Where the Council Clashes

D-first vs A-first: The Executor wants to run MC immediately (two-day task, just see what happens). The Contrarian insists on auditing the optimizer first (running MC on a broken optimizer produces confident garbage). The pragmatic case for A-first is speed. The engineering case for D-first is correctness.

Opponent model: The First Principles Thinker argues the opponent model is the whole ballgame — if simulated opponents pick chalk, you're validating against yourself. Others treat it as a solvable input assumption.

Blind Spots the Council Caught

  • Undefined objective function: Does the optimizer maximize expected score, expected rank, or win probability? These are different objectives producing different picks. If it maximizes expected score, it systematically underweights upsets.
  • Brier advantage may be round-concentrated: Noseed's edge across 1071 games could live entirely in early rounds (10 pts each) while Final Four picks (320 pts each) drive pool outcomes. Nobody checked.
  • Pool scoring format unspecified: Standard, upset bonus, seed-differential — MC results are only valid for the scoring system tested.

The One Thing to Do First

Write a synthetic optimizer audit. Construct a probability vector by hand where one team has a manually inflated win probability vs chalk expectations. Run it through the optimizer. Verify it recommends the underdog as a leverage pick. If it doesn't, the optimizer is broken and nothing else matters. If it does, you've cleared the gate for Monte Carlo.
Contrarian Full Response

The fatal flaw is treating a measurement problem as a modeling problem. Option C is a trap — better models don't buy statistical power. Option B is intellectually dishonest. The REAL problem is Option D being glossed over. "Zero leverage picks" from seed mode isn't a curiosity — it's evidence the bracket translation layer is broken. If the optimizer correctly maximized EV on seed probabilities, it wouldn't produce chalk. Before Monte Carlo, audit the optimizer on seed mode first. Running MC on a potentially broken optimizer produces confident-looking garbage faster. Sequence: audit optimizer, then MC, then run across years.

First Principles Thinker Full Response

The wrong question is "which mode wins pools?" The right question is "does probability accuracy translate to pool EV at all, and through what mechanism?" The link hasn't been validated. Better Brier means calibrated probabilities, but pool EV depends on leverage — picking undervalued teams. A calibrated model can destroy pool EV if everyone uses the same calibration. The seed mode "zero leverage" finding tells you the optimizer works — it detects no deviation from consensus. But the critical question: what is your opponent model? If MC assumes opponents pick chalk, you've built a circular system. Validate the opponent model FIRST.

Expansionist Full Response

The 17-year power problem is solved — simulate 17,000 pools from existing data. MC quantifies upside in dollar terms. "Better Brier, p=0.0006" means nothing to pool participants. "23% higher expected pool value" is actionable. Hidden opportunity: segment by pool size. Adjacent opportunity: publishable research. Ship blend as default but don't let "pool EV inconclusive" be the final word. Option A now.

Outsider Full Response

Option A is the obvious next move. 17 data points to detect a signal that happens once a year — of course it's inconclusive. Monte Carlo doesn't require waiting 17 more years. If you believe the Brier improvement is real, simulate to find out if that edge survives bracket scoring noise. Ship as-is means you built a better prediction engine and then shrugged.

Executor Full Response

Option A. Monday morning, write the Monte Carlo simulator. A pool simulator is a loop: simulate 500 pools with N random entrants from realistic pick distributions, run three modes as entries, score them. Pick one year first. Half-day of work. If noseed wins at 55%+ frequency, you've closed the loop. Skip C and D. Two-day task.

Peer Review Highlights

All 5 reviewers ranked the Contrarian as strongest for identifying the audit prerequisite.

Biggest blind spot flagged: First Principles Thinker's suggestion to collect ESPN data was called impractical by 4/5 reviewers.

What everyone missed (reviewer consensus): The optimizer's objective function (expected score vs win probability), round-concentration of Brier gains, and scoring format sensitivity.
