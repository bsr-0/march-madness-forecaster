Create a well-structured git commit for the current changes.

1. Run `git status` and `git diff --cached --stat` to see what's staged
2. If nothing staged, identify logical groups of changes to stage
3. Write a concise commit message following conventional commits (feat/fix/refactor/docs/test)
4. The message should explain WHY, not just WHAT
5. Stage the relevant files and commit

If changes span multiple concerns, suggest splitting into multiple commits.
