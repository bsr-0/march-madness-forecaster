# O19 — Pre-2011 ESPN Public Picks Decision

**Date:** 2026-04-14
**Branch:** `claude/simplify-repo-structure-keQXE`
**Status:** closure evidence for `COUNCIL_LESSONS.md §2 O19`

## Gate (from §2)

> Pre-2011 ESPN picks data — exclude, down-weight, or equivalent.
> Decision + implementation. Field expanded 64 → 68 in 2011; analytics-
> culture shift.

## TL;DR

**Decision: keep on disk for single-year historical fidelity, exclude
from any aggregated calibration window.** The status-quo behavior is
correct but wasn't explicit in code. This closure makes it explicit.

Empirical basis: pre-2011 is measurably chalkier than post-2011 (both
in the public's picks and the actual tournament outcomes). Pooling the
two regimes into an opponent-model calibration would skew it chalky
for predicting a post-2011 pool. But simulating the 2008 pool requires
the 2008 public's actual picks — throwing away the file would destroy
historical fidelity.

## The data

| Metric | Pre-2011 (2008-2010) | Post-2011 (2011-2024, ex 2020) |
|---|---|---|
| Years | 3 | 14 |
| Mean champion seed | **1.00** (all 3 were 1-seeds) | **1.86** |
| Non-1 champions | 0/3 (0%) | 3/14 (21%) — 2011 UConn (3), 2014 UConn (7), 2023 UConn (4) |
| Mean seed-1 pick rate at S16 | 81.6% | 67.1% (Δ = **+14.5 points chalky**) |
| Mean seed-1 pick rate at E8 | 57.1% | 44.5% (Δ = +12.6 points chalky) |
| Mean seed-1 pick rate at F4 | 33.9% | 25.6% (Δ = +8.4 points chalky) |
| Mean seed-1 pick rate at CHAMP | 18.9% | 14.1% (Δ = +4.9 points chalky) |
| Mean \|Δ\| across 96 (seed,round) cells | — | 0.018 |
| P(\|Δ\| > 5 points) | — | 9 / 96 cells (9.4%) |

The public's pre-2011 over-picking of 1-seeds isn't irrational — it
matched the actual chalky regime. But treating pre-2011 as
representative of post-2011 *pool behavior* would embed a systematic
chalky bias.

## What's already correct in the codebase

1. **`SEED_PICK_RATES` in `src/data/seed_pick_model.py`** is calibrated
   from **2015-2024** aggregate data only (module docstring line 307).
   Pre-2011 was never in the calibration window.
2. **`scripts/mc_pool_backtest.py` `BACKTEST_YEARS`** starts at 2011
   (line 74). The production pool backtest never touches 2008-2010.
3. **Archived pre-2011 files exist on disk** and load cleanly when a
   single-year simulation asks for 2008/2009/2010. They are genuine
   ESPN "Who Picked Whom" data from the `dlm1223/march-madness`
   archive, not synthetic.

What was **missing** pre-closure: any of this was documented or
enforced in code. A future caller could pool 2008-2025 picks into a
calibration set without triggering any alarm.

## What this closure changes

Single targeted edit at `src/data/historical_picks.py`:

1. **New module-level constant**
   ```python
   MIN_PICKS_CALIBRATION_YEAR = 2011
   ```
   documents the boundary for any future aggregator to consult.

2. **Extended module docstring** records the O19 decision, the
   empirical basis (chalky-bias deltas table), and the usage contract:
   *"Callers that aggregate across years MUST either honor
   `MIN_PICKS_CALIBRATION_YEAR` or pass `strict_post_2011=True` to
   raise on pre-2011 years."*

3. **New `strict_post_2011: bool = False` kwarg** on
   `load_historical_public_picks`. Pre-2011 caller use with
   `strict_post_2011=True` raises a `ValueError` pointing back to this
   audit.

The archived JSON files themselves are unchanged — single-year
historical simulations continue to work exactly as before.

## Residual risks & non-gates

- **A future script could start pooling across years.** The new
  `strict_post_2011` kwarg is opt-in, not enforced globally. This is
  intentional — the single-year callers above should NOT break. Any
  future aggregator needs to be coded to pass the flag; the lock test
  catches the constant disappearing but can't catch every misuse.
- **n = 3 for pre-2011.** The chalky-bias numbers (Δ = +14.5 at S16
  etc.) come from only 3 years. The direction is consistent across
  rounds and matches the actual-outcome shift (0/3 vs 3/14 non-1
  champions), but confidence intervals are wide. This is documented
  here so future revisits know the sample size.
